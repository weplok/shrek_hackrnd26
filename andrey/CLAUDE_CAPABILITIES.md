# Claude Code: инструменты, возможности и как их применять

Справочник по тому, что умеет Claude Code (модель Claude Opus 5.5) в этом окружении, и как этим правильно пользоваться.

> Набор инструментов зависит от сессии: подключённых MCP-серверов, плагинов, режима разрешений и аккаунта. Здесь описано то, что доступно в текущей сессии.

---

## 1. Как со мной работать (коротко)

- **Пишите задачу целиком и конкретно.** «Добавь кнопку смены темы в `andrey/index.html`, цвета хранить в CSS-переменных» лучше, чем «сделай тему».
- **Указывайте файлы и пути**, если знаете. Я и сам найду, но так быстрее.
- **Говорите критерий готовности:** «пусть проходят тесты», «проверь в браузере», «закоммить и запушь».
- **Коммиты и пуши я делаю только по просьбе.** Если вы на `main`, я сначала создам ветку.
- **Рискованные действия** (удаление, `force push`, отправка во внешние сервисы) я сначала подтверждаю.
- **Команду в своём терминале** можно запустить прямо из чата: `! <команда>` (например, `! gh auth login`). Вывод попадёт в разговор.

## 2. Работа с файлами и кодом

| Инструмент | Что делает | Когда применять |
|---|---|---|
| **Read** | Читает файл (текст, картинки, PDF, Jupyter-ноутбуки) | Посмотреть код, скриншот, PDF. Для больших файлов — по частям (`offset`/`limit`) |
| **Write** | Создаёт файл или полностью перезаписывает его | Новые файлы или полная замена содержимого |
| **Edit** | Точечная замена строки в файле | Правки в существующем коде. Фрагмент должен совпадать точно и быть уникальным |
| **NotebookEdit** | Редактирует ячейки `.ipynb` | Работа с Jupyter-ноутбуками |
| **Bash** | Выполняет команды в shell | git, npm/pip, сборка, тесты, `grep`/`find`, запуск скриптов. Может работать в фоне (`run_in_background`) |
| **Monitor** | Ждёт выполнения условия (например, пока поднимется сервер) | Вместо `sleep`, когда надо дождаться события |

**Как правильно:**
- Просите правку → я читаю файл, вношу минимальное изменение в стиле окружающего кода.
- Для долгих процессов (dev-сервер, сборка) я запускаю их в фоне, а вы продолжаете общаться.
- Временные файлы я кладу в отдельную scratchpad-папку сессии, а не в проект.

## 3. Git и GitHub

Через **Bash** доступны `git` и `gh` (GitHub CLI):

- коммиты, ветки, `diff`, `log`, `rebase` (кроме интерактивных режимов вроде `git rebase -i`);
- создание PR: `gh pr create`, просмотр issues, комментариев, статуса CI.

**Пример запроса:** «Закоммить изменения в `andrey/` и открой PR в `main`».

## 4. Поиск и интернет

| Инструмент | Что делает | Когда применять |
|---|---|---|
| **WebSearch** | Поиск в интернете. Режимы `standard` (быстро) и `extended` (глубже, свежее, дороже) | Свежая документация, версии библиотек, новости, ошибки |

## 5. Агенты (субагенты)

Инструмент **Agent** запускает отдельного агента, который работает в фоне и возвращает результат. Я запускаю их **только когда вы об этом просите**: каждый агент стартует с нуля и стоит дополнительных ресурсов.

| Тип | Для чего |
|---|---|
| `general-purpose` / `claude` | Любая многошаговая задача |
| `Explore` | Широкий поиск по большой кодовой базе (только чтение) |
| `Plan` | Проектирование плана реализации, архитектурные решения |
| `claude-code-guide` | Вопросы о самом Claude Code, Agent SDK, Claude API |
| `fork` | Моя копия с полным контекстом разговора, работает параллельно |
| `statusline-setup` | Настройка статус-строки Claude Code |

Связанные инструменты: **SendMessage** (написать уже запущенному агенту), **ListAgents** (список агентов), **TaskStop** (остановить задачу).

Параметр `isolation: "worktree"` даёт агенту отдельный git worktree, чтобы он не мешал вашим файлам.

**Пример:** «Запусти Explore-агента: найди все места, где используется `script.js`».

---

## 6. Планирование и worktree

- **EnterPlanMode / ExitPlanMode** — режим планирования: я изучаю код и предлагаю план, ничего не меняя, пока вы его не одобрите. Удобно перед большими изменениями.
- **EnterWorktree / ExitWorktree** — работа в отдельном git worktree (изолированная копия репозитория).
- **AskUserQuestion** — задаю вопрос с вариантами ответа, когда решение действительно за вами.

## 7. Расписание и повторяющиеся задачи

| Инструмент / skill | Что делает |
|---|---|
| `/loop` | Повторять команду с интервалом (`/loop 5m /foo`) или в собственном темпе |
| **ScheduleWakeup** | Внутри `/loop`: «разбудить» себя через N секунд |
| **CronCreate / CronList / CronDelete** | Локальные задачи по расписанию |
| `/schedule` | Облачные агенты (routines) по cron или разовый запуск в заданное время |
| **RemoteTrigger** | Запуск удалённых триггеров |
| **PushNotification** | Отправить вам уведомление |

**Пример:** `/loop 10m проверь, прошёл ли CI в PR #3`.

## 8. Artifacts — веб-страницы на claude.ai

Инструмент **Artifact** публикует HTML-страницу на claude.ai. По умолчанию она приватная, ссылкой можно поделиться.

Подходит для:
- дашбордов, отчётов, демо, интерактивных страниц, небольших игр;
- страниц с «живыми» возможностями: общее состояние между зрителями, база данных (**ArtifactData**), комментарии (**ArtifactComments**), загрузка файлов, вопросы к Claude прямо со страницы.

Действия: `publish`, `read`, `list`, `open`, `delete`, `pin`/`unpin`, `quickstart` (подобрать готовый тип: слайды, документ, дизайн, дашборд).

**Пример:** «Опубликуй сайт из `andrey/` как артефакт, чтобы показать команде».

Ещё есть **DesignSync**: синхронизация с дизайн-системами.

## 9. Claude Docs — живые документы

MCP-сервер **Claude Docs** (`batch`, `update`, `guide`, `create`, `read`, `query`, `export`, `delete`) создаёт редактируемые документы на claude.ai с комментариями и совместной работой. Документ можно экспортировать в Word, PDF, Markdown или Google Docs.

**Когда:** нужен документ для людей (отчёт, ТЗ, гайд), а не файл в репозитории. Если документ должен лежать в коде, как этот `.md`, просите файл.

## 10. Skills (навыки) и slash-команды

Skill — готовая инструкция под конкретный тип задач. Вызываются через `/имя` или автоматически, когда задача подходит.

### Разработка
| Команда | Назначение |
|---|---|
| `/code-review [low…max\|ultra]` | Ревью диффа или PR на баги. `--fix` применяет исправления, `--comment` оставляет комментарии в PR |
| `/code-review ultra` | Глубокое многоагентное ревью в облаке (запускаете вы, платно) |
| `/simplify` | Упростить и почистить изменённый код (качество, без поиска багов) |
| `/security-review` | Ревью безопасности изменений в ветке |
| `/run` | Запустить приложение и проверить, что изменение работает |
| `/init` | Создать `CLAUDE.md` с описанием проекта |
| `claude-api` | Справка по Claude API / Anthropic SDK |

### Настройка Claude Code
| Команда | Назначение |
|---|---|
| `update-config` | Правки `settings.json`: разрешения, хуки, env-переменные |
| `/fewer-permission-prompts` | Собрать allowlist частых безопасных команд, чтобы реже спрашивать разрешения |
| `keybindings-help` | Настройка горячих клавиш |
| `plugin-authoring` | Создание модов: панели, статус-строка, хуки, свои slash-команды |

### Документы и файлы
| Skill | Назначение |
|---|---|
| `docx`, `xlsx`, `pptx`, `pdf` | Создание и редактирование Word, Excel, PowerPoint, PDF |
| `docs` | Живые документы Claude Docs |
| `google-workspace` | Google Docs / Sheets / Slides |
| `dataviz` | Графики и визуализации данных |
| `artifact-design`, `artifact-diagramming`, `artifact-capabilities` | Дизайн, диаграммы и «живые» возможности артефактов |

### Прочее
| Skill | Назначение |
|---|---|
| `deep-research` | Большое исследование по многим источникам с итоговым отчётом |
| `claude-in-chrome`, `built-in-browser` | Управление браузером: клики, формы, скриншоты, консоль |
| `computer-use` | Управление приложениями на компьютере (через desktop-приложение Claude) |
| `skill-creator` | Создать свой skill |
| `import-memory` | Импорт памяти из другого AI-ассистента |
| `morning` | Утренний брифинг |

## 11. Память между сессиями

У меня есть постоянная файловая память для этого проекта (`~/.claude/projects/.../memory/`). Туда я записываю:
- кто вы и как предпочитаете работать;
- ваши замечания («не делай так», «вот так хорошо»);
- контекст проекта, которого нет в коде (дедлайны, договорённости);
- ссылки на внешние ресурсы.

**Как применять:** скажите «запомни, что…», и в следующих сессиях я это учту. «Забудь…» удаляет запись.

Для постоянных инструкций по проекту, которые должны быть видны всей команде, лучше `CLAUDE.md` в репозитории (`/init`).

---

## 12. Хуки и автоматизация

«Каждый раз, когда…», «перед коммитом всегда…» — это **хуки** в `settings.json`. Их выполняет сам Claude Code, а не я по памяти, поэтому они срабатывают надёжно. Настраиваются через `update-config`.

**Пример:** «Сделай хук, чтобы после каждого редактирования `.js` запускался prettier».

## 13. Чего я не делаю / ограничения

- Не коммичу и не пушу без вашей просьбы.
- Не запускаю субагентов без явного запроса.
- Не публикую страницы, выдающие себя за реальных людей или организации, и поддельные документы.
- Не помогаю с вредоносной деятельностью (DoS, атаки на чужие системы и т.п.). Пентест, CTF и защитная безопасность — пожалуйста, с понятным контекстом.
- Интерактивные команды (`git rebase -i`, логин в браузере) запускайте сами через `! <команда>`.
